# 多镜头场景的拍摄现场还原（摄影机方案 + 灯光方案 + 俯视教学视频）

来源项目：《周处除三害》灵修堂屠杀戏（原片 1:45:06.6–1:52:50.1，7′43″，138 个镜头 → 25 个机位方案、9 组光源）。
和 film-set-reconstruction（长镜头、跟机位走）的区别：这里是**很多镜头剪成的一场戏**，产物是**固定的俯视现场**，随成片时间轴高亮“这一秒是哪台机拍的”。

全程用中文和用户沟通。所有过程文件放 `项目/work/`，交付物放 `项目/输出/`。

## 0. 开工前确认

1. 精确的起止时间码（之后用剪辑点修正到帧）。
2. 交付版式（下面「交付默认值」是用户确认过的终版，没别的要求就用它）。
3. 俯视图留透视（能看出机高、灯高）；群演按座位批量摆、不逐个对位——重点是机位和灯。
4. Mac 保持唤醒、Blender 开着并 Start MCP Server；不重启、不关闭、不保存用户的 .blend（交付时用 `save_as_mainfile(copy=True)` 另存一份）。
5. 先跟用户说清楚一个上限：**成片里分不出“多机同拍”和“一台机换机位分次拍”**。还原的单位是“机位方案（setup）”，A、B、C… 编号；只在有证据时注明“推断为 A/B 双机同拍”。
6. 查制作资料：地方影视委员会协拍页、幕后访谈（取景地、实景还是搭景、铺轨、摄影师名）。《周处》的关键事实（旧士林分局三楼礼堂、地面铺轨、彩色灯）就来自台北市影视委员会页面。

## 2. 第 1 步：切片与剪辑点

- `cropdetect` 找黑边（《周处》网飞版：`crop=1920:804:0:138`，字幕烧在画面里）。
- 先做一个 480×200、全 I 帧（`-g 1`）的代理片，后面所有逐帧分析都在代理上跑，快：
  `ffmpeg -ss T0 -i src -frames:v N -vf "crop=...,scale=480:200" -an -c:v libx264 -preset ultrafast -crf 20 -g 1 proxy_take.mp4`
- 剪辑点检测（cv2）：每帧裁掉底部字幕带，算 64×24 LAB 缩略图差 + HSV 直方图 L1，`D = 0.5*thumb/40 + 0.5*hist`，取局部极大。
  - `D≥0.4` 且 `back≥0.3` → 硬切；`0.2–0.4` → 疑似，标 `?` 人工看。
  - **闪光测试**：`back = min(d(i-1, j), j∈i+1..i+4)`。`back<0.16` 且亮度上升 → 枪口闪光/闪烁，**不是剪辑点**。屠杀戏里这类很多。
- 做 shot sheet（每镜头首/中/尾三张）逐页看，把误切合并（《周处》合并了 12 个）。
- 帧号约定：take 帧号从 0 开始，`t = f/24`；原片时间 = `T0 + f/24`。

## 3. 第 2 步：镜头运动统计

每对相邻帧：`goodFeaturesToTrack`（遮字幕）→ LK 光流 → `estimateAffinePartial2D`（RANSAC 1 px）。
累计：`zoom = exp(Σ log s)`、平移、旋转；`jit` = 平移二阶差分的标准差；`par` = 相似变换后的残差中位数（视差）。
判读：`zoom` 明显偏离 1 且 `par` 小 → 变焦推拉；`jit > 1` → 手持；`par` 大且平滑 → 轨道/斯坦尼康；全接近 0 → 固定。
然后对每个镜头取中间帧，用原片全分辨率抽出（`-ss` 放 `-i` 前，减 0.02 s）。

## 4. 第 3 步：机位归并（最需要人眼的一步）

- 把中间帧拼成 4×5 印样，标注镜头号、时长、z/j/p，**全部看完**。
- 归并规则：背景构图相同（同一面墙、同一组物体的相对位置）+ 景别接近 → 同一机位；同机位换焦段（变焦镜头的广/长端）仍算一个机位，镜头表里逐镜头记实际视角。
- 常见结构：两台机背靠背架在人群中、一台朝门一台朝台、都用长焦 → 这场戏的主力（《周处》E+U 占出画时长近一半）。
- 插入镜头（腰包、手部）、贴地仰拍、门外楼梯跟拍：单独成机位，可信度标“低”。
- 同时列勘景清单：墙、门（门框、侧扇玻璃、门楣）、窗与纱帘、壁柱、壁灯、空调柜、鞋架/供桌、舞台（高度、台阶形状）、幕布、画像、乐器、坐垫、门外走廊与楼梯。

## 5. 第 4 步：空间与机位反求

### 5.1 参数化房间 + 标定点
给每个可辨认的点起名字，坐标写成房间参数的函数（米制，x 东、y 北、z 上，南墙门口 y=0）：
门框四角 `DET/DWT/DEB/DWB`、门横档 `DXE/DXW`、开启扇 `OEB/OWB`、空调柜 `ACWT/ACET/ACWB/ACEB`、门两侧壁灯 `SCE/SCW`、台口两端 `SFWT/SFWB/SFET/SFEB`、画像四角 `PWT/PET/PWB/PEB`、侧门 `NDW_TS…`、侧壁灯 `SNW1…`。
人：`CH_H`（头顶 1.80 m）、`CH_F`（脚 0.03 m）——每个视图里人的位置是自由变量。
竖直线约束 `VL`：给两点 `[[u1,v1],[u2,v2]]`，残差 = 该线与竖直消失方向的垂距。

在原片帧上叠 100 px 网格（关键处 20 px 放大图）读像素坐标，写进 `obs_vN.json`。

### 5.2 相机模型（全程统一）
```python
def Rmat(yaw, pitch, roll=0):          # yaw: 0=+Y(北) 顺时针为正；世界→相机，OpenCV x右 y下 z前
    y,p,r = map(math.radians,(yaw,pitch,roll))
    f = np.array([math.sin(y)*math.cos(p), math.cos(y)*math.cos(p), math.sin(p)])
    r0 = np.array([math.cos(y), -math.sin(y), 0.]); u0 = np.cross(r0, f)
    rr = r0*math.cos(r)+u0*math.sin(r); uu = -r0*math.sin(r)+u0*math.cos(r)
    return np.vstack([rr, -uu, f])
def proj(X, C, R, f, k1=0):            # 1920×804：CX=960 CY=402
    q = R@(X-C); x,y = q[0]/q[2], q[1]/q[2]; d = 1+k1*(x*x+y*y)
    return np.array([960+f*x*d, 402+f*y*d]), q[2]
```

### 5.3 求解顺序
1. **SfM 打底拿焦距和相对位置**：每镜头一张中间帧（1280 宽、遮字幕），pycolmap 4.x：`extract_features(PER_IMAGE, SIMPLE_RADIAL)` → `match_exhaustive` → `incremental_mapping`。会得到几个子模型（朝南一组、朝北一组），同机位的镜头 C 几乎重合——这是归并机位的硬证据，焦距（HFOV）也比消失点稳。
2. **联合 BA**：房间参数 + 每视图 (C, yaw, pitch, roll, log f, k1) + 人位置，`least_squares(loss='soft_l1', f_scale=2, jac_sparsity=…)`。
   - 用**有限差分探测出的精确稀疏结构**，否则一次几分钟都不收敛。
   - 先固定房间只解相机，再全放开。
   - **一定多起点**（厅长 14/17/20 m × 焦距 1300/2400 px）：长焦和厅深是耦合的，单起点会掉进“相机跑出房间”或“f→0”的局部解。挑残差小**且物理合理**（机位在房内、机高 0.3–2.5 m）的解。
   - 弱先验：门高、侧门高、空调高、人高、同一人在不同视图的位置互相拉住。
3. **定房间、逐机位 PnP**：房间参数四舍五入写死（《周处》：宽 10.4、台口 y=17.8、台深 4.8、台高 0.5、门中心 x=0.14 半宽 1.73），每个机位单独拟合；焦距用 SfM 的值加 1% 先验。
4. **SfM 其余镜头搬进世界**：用 3–4 个 PnP 解好的参考机位（中心 + 前方 4 m 点）做 Umeyama 相似变换，把整组 SfM 相机变到米制世界。
5. 没有标定点的手持近景：按画面内容推断位置（离人多远、多高、朝哪），可信度标“低”。

### 5.4 线框验收（几秒一轮，不用 Blender）
把房间边线、门、空调柜、画像、侧门投到原片帧上，四宫格看。对不上就改 obs 或机位，重跑。

## 6. 第 5 步：灯光推断

逐类写证据：
- 窗 + 纱帘：亮度均匀的巨型柔光（侧逆光，墙几乎无影）——通常是主光；大窗外常有 HMI 维持多日一致，但无直接证据要标“推测”。
- 画内实用光：天花灯盘、壁灯、画像背光、发光道具（石雕）——可信度高。
- 看人脸：高光位置、阴影方向、眼神光判断主光方位；背景压黑多半是挂了黑幕（负补光）。
- 画外不可见又解释不了的亮度 → “推测”，写清楚理由。
每盏灯给编号 L1…，后面所有图和视频都用这个编号。

## 7. 第 6 步：Blender 场景（一个模块化脚本，改完重跑）

数据一律放 `plan_data.json`：`setups`（id、name、C、yaw、pitch、hfov 列表、rig、move、conf、shots、note、color）、`shots`（n、f0、f1、t0、t1、tc、dur、setup、phase、phase_name、hfov）、`chen`（主角路径关键帧 `[t,(x,y)]`）、`lights`、`people`。

构建模块要点：
- `reset_scene()` 用单独场景名，清自己的集合；EEVEE、Standard 色彩变换、`film_transparent=True`（面板合成时铺底色）。
- 墙体剖切：西/南/北墙 3.2 m、东墙压到 1.0 m，墙顶加深色剖切面——俯视时看得到墙厚和窗。
- 机位：空物体为父，下挂机身（发光色块）、**视锥（半透明面 + Wireframe 修改器描边）**，变焦机位再挂一个长端视锥；支架按 rig 生成三脚架/高脚架/顶拍臂，手持则放一个操作员小人；地面光圈只在当前机位显示。
- 灯：窗外发光面板 + 半透明光束楔形；天花灯盘、布幔上方顶光用 Wireframe 描边；壁灯小球；画像四边光晕；发光石雕。另加真实面光 + 一盏弱太阳光保证可读。
- **所有示意几何体关阴影**：`obj.visible_shadow = False`（视锥、光束、光圈、纱帘…），否则地面一片黑。
- 材质按名字复用（`lx_<名>`），颜色键入名字里，避免重建时错色。
- 人物：三种简模网格（坐 / 站 / 躺 / 持枪站）共用，`set_people(t)` 每镜头切换网格和可见性。
  - 群演：按排生成坐垫座位，**中间留主角通道**；每人分配 `flee`（起身时刻、离场时刻按离门距离）或 `stay`（倒下时刻按主角走到那一排的时间）。
  - 主角走位：关键帧线性插值；朝向按段落规则；持枪段换持枪网格。
- **俯视相机自己拼矩阵，不要用 to_track_quat**（会得到错误的滚转，厅变成竖的）：
```python
look = Vector((-cos(pt), 0, -sin(pt)))          # 从东侧上方看向西：画面右=北(舞台)，左=南(门)
loc = Vector(target) - look*dist
z = -look.normalized(); up = Vector((0,0,1))
y = (up - z*up.dot(z)).normalized(); x = y.cross(z)
M = Matrix((x,y,z)).transposed().to_4x4(); M.translation = loc; cam.matrix_world = M
```
  《周处》参数：target (0.4, 8.4, 0)、dist 42、pitch 58°、lens 50 mm、1080×620。
- 同机位验收相机 `CHK_FilmCam`：`lens = 18/tan(hfov/2)`（36 mm 宽画幅），1280×536，渲染时隐藏所有示意物，try/finally 恢复设置。

## 8. 第 7 步：渲染驱动（在用户 Blender 里用 timer）

`start_top_renders(out_dir)`：`bpy.app.timers` 每 tick 渲 3 个镜头；每个镜头 `prep_shot`（人物状态取镜头中点、只显示本段机位、当前机位亮 + 视锥按本镜头实际视角重建）→ 渲染 PNG → 用 `world_to_camera_view` 记录**锚点**（每台机、主角、关键人物、每盏灯的屏幕坐标）→ 最后写 `anchors.json` 和 `_DONE`。
《周处》138 张约 70 秒。
**锚点是按当时的渲染分辨率算的**：换分辨率渲总图时，锚点已经是新分辨率，不要再乘倍数。

### 9.2 编码（重要：device_bash 会杀掉后台进程）
`nohup … &`、`setsid` 在 device_bash 调用返回后都会被杀，后台编码会留下截断的半个文件。
做法：把镜头按 ~40 s 分成 11 段，每段一次前台 ffmpeg（≈17 s/段），一次 device_bash 调用跑 4–7 段：
```
-f concat -i list_k.txt                       # 面板 PNG，duration = 镜头帧数/24，末张重复
-ss (T0+t0) -i 原片
-loop 1 -framerate 24 -i zoom_strip.png  /  playhead.png  /  playhead_zoom.png
[0:v]fps=24,setpts=N/24/TB[bg];
[1:v]crop=1920:804:0:138,scale=1080:452,fps=24,setpts=N/24/TB[film];
[bg][film]overlay=0:80[a];
[2:v]crop=1040:56:x='(t+t0)*30':y=0[z];[a][z]overlay=20:606[b];
[b][3:v]overlay=x='19+(t+t0)*1040/TOTAL':y=565[c];[c][4:v]overlay=x=539:y=604
-frames:v <本段帧数> -an -c:v libx264 -preset veryfast -crf 20
```
纵坐标从合成脚本写出的 `layout.json` 读（y_film / y_strip / y_head / y_headz），换版式不用改编码脚本。
最后 concat 各段 `-c:v copy`，同时 `-ss T0 -i 原片 -map 1:a:0 -ac 2 -t 总长` 整体铺原声。
检查：`ffprobe -count_frames` 帧数 = 所有镜头帧数之和；在段落接缝前后和几个镜头中间抽帧拼成一行看同步。

## 11. 踩过的坑

1. **同一路径重复写回 Mac，拿到的还是旧内容**（device_commit_files）→ 每次换文件名（`lxt_build_v3.py`、`_v4`…），Blender 里用 `importlib.util.spec_from_file_location` 按文件路径加载，别靠 `importlib.reload`。
2. **后台进程被杀**（见 9.2）。中间产物删不掉时 `mv` 到 `_to_delete/`，告诉用户自己删。
3. **俯视相机滚转错**（厅竖过来）→ 显式拼矩阵。
4. **地面全黑**：示意几何体投阴影 → 全部 `visible_shadow=False`；窗光束 alpha 降到 0.1。
5. **锚点翻倍**：换分辨率后又乘了 2，标签全飞出画面。
6. **BA 不收敛 / 解到房间外**：用精确稀疏结构 + 多起点 + 物理合理性筛选。
7. **枪口闪光被当成剪辑点** → 闪光测试。
8. **群演挡住主角走位** → 生成座位时留通道。
9. 字幕卡和说明里**不要转写歌词**（版权）；只写剧情和机位。
10. 别把推断说成事实：多机同拍、画外灯，都写“推断/推测”。
