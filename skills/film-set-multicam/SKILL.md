# 多镜头场景的拍摄现场还原（摄影机方案 + 灯光方案 + 俯视教学视频）

来源项目：
- 《周处除三害》灵修堂屠杀戏（7′43″，138 个镜头 → 25 个机位方案、9 组光源）：实景、铺轨、多机位分次拍。
- 《让子弹飞》鸿门宴（36:14–46:21，10′10″，308 个镜头）：搭景、**环形轨道三机同拍**、机位镜头内持续移动、Rodin 真人机组。

和 film-set-longtake（长镜头、跟机位走）的区别：这里是**很多镜头剪成的一场戏**，产物是**俯视现场**，随成片时间轴高亮“这一秒是哪台机拍的、它怎么动、用什么参数拍”。
用途是给影视专业学生看的教学视频：**拍摄现场要像真的**（真人机组、真实相机、动的机位），标注要克制，不能挡住人物。

全程用中文和用户沟通。所有过程文件放 `项目/work/`，交付物放 `项目/输出/`。

## 0. 开工前确认

1. 精确的起止时间码，以及首尾是否包含某个切点/反应镜头（之后用剪辑点修正到帧）。
2. 交付版式（第 10 节是用户确认过的终版，没别的要求就用它）。
3. 俯视图留透视（能看出机高、灯高）；群演按座位批量摆、不逐个对位——重点是机位和灯。
4. **Blender 安全**（这一条最重要，见第 12 节的崩溃记录）：
   - 开工前请用户**先保存自己正在做的东西**；崩溃过两次都丢了用户没存的场景。
   - 每次写操作前打印 `bpy.data.scenes` 和 `bpy.context.scene.name`：如果出现不是自己的场景（另一个任务正在用同一个 Blender），**不要切换、不要 frame_set、不要改它的 render.filepath**，先问用户；最好让本项目独占一个 Blender。
   - 不重启、不关闭、不保存用户的 .blend；交付用 `save_as_mainfile(copy=True)` 另存。
5. Rodin（hyper3d）要用就确认已开；它是**按场景的属性**，新建场景要把 `scene.blendermcp_use_hyper3d=True`。
6. 先跟用户说清楚上限：**成片里分不出“多机同拍”和“一台机换机位分次拍”**，也分不出是 35 条里的哪一条。还原单位是“机位方案（setup）”；只在有证据时注明“推断为同拍”。
7. 查制作资料：地方影视委员会协拍页、摄影指导/导演访谈（取景地、实景还是搭景、铺轨、几台机、多少人）。《周处》：旧士林分局礼堂、地面铺轨；《让子弹飞》：赵非谈环轨外径约 6 m、三机固定在环轨上不停转、景约 5 米多拆了一部分，姜文谈三机同步、每台机 5 个人。查不到的（如收音方式）写“推断”。

## 2. 第 1 步：片源、切片与剪辑点

- **先查帧率和重复帧**：WEB-DL 常见 29.97 fps、每 5 帧重复 1 帧（《让子弹飞》）。用 `decimate` 还原 23.976（时基 1001/24000），**整场只从同一个起点 decimate 一次**，生成 `film_take.mp4`（去黑边、缩到 1080 宽），后面所有编码都从它按帧号取。分段各自 decimate 会让各段起点错开 1 帧。
- `cropdetect` 找黑边：《周处》`1920:804:0:138` 字幕烧在画面里；《让子弹飞》同样裁切，字幕在下黑边里，裁掉就干净。
- 代理片：480×200、全 I 帧（`-g 1`），逐帧分析都在代理上跑。
- 剪辑点（cv2）：64×24 LAB 缩略图差 + HSV 直方图 L1，`D = 0.5*thumb/40 + 0.5*hist`，取局部极大。硬切通常 ≥0.4–0.47，噪声 <0.2，中间的标 `?` 人工看。
  - **闪光测试**：`back = min(d(i-1, j), j∈i+1..i+4)`；`back<0.16` 且亮度上升 → 枪口闪光，不是剪辑点。
- shot sheet（首/中/尾三张）逐页看，合并误切。
- 帧号约定：场景帧号从 0 开始，`t = f*1001/24000`；原片时间 = `T0 + t`。镜头记录 `f0, f1, nf, t0, t1, dur, tc`。

## 3. 第 2 步：镜头运动统计

每对相邻帧：`goodFeaturesToTrack`（遮字幕）→ LK 光流 → `estimateAffinePartial2D`（RANSAC 1 px）。累计 `zoom = exp(Σ log s)`、平移、旋转；`jit` = 平移二阶差分标准差；`par` = 相似变换残差中位数。
判读：`|log zoom|>0.12` 且 `par` 小 → 变焦；`jit>1` → 手持；`par` 大且平滑 → 轨道/斯坦尼康；全接近 0 → 固定。分类写成 `cat`：S 静 / M 动 / H 手持甩镜。
每镜头中间帧用原片全分辨率抽出（`-ss` 放 `-i` 前）。

## 4. 第 3 步：机位归并 + 逐镜头标签

- 中间帧拼 4×5 印样，标镜头号、时长、z/j/p，**全部看完**。
- 同背景构图 + 景别接近 → 同一机位；同机位换焦段仍算一个机位，逐镜头记实际视角。
- 逐镜头标“拍谁/拍什么”的字母（如 H/Z/T 三个主角、X 人质、C 布帘、G 某角色、A 动作模糊、B 道具、E 外景），后面分组 SfM、景别、标签都靠它。
- **人物名用片中叫法**（《让子弹飞》里是「黛玉晴雯」，不是“舞女”），不要自己起泛称。
- 插入镜头、贴地、手持甩镜单独成机位，可信度标“低”。
- 勘景清单：墙、门窗、帘、壁柱、壁灯、烛台、盆栽、楼梯、小隔间、道具（剑、首饰匣、酒瓶）。
- **故事里会变的东西也要列**：布帘溅血（哪几镜开始、几个阶段）、人物从站到蹲/跪、道具出现/消失的镜头号。

## 5. 第 4 步：空间与机位反求

### 5.1 参数化房间 + 标定点（实景、有明确结构时）
给可辨认点起名字，坐标写成房间参数的函数（米制，x 东、y 北、z 上）。人用 `CH_H`（头顶）`CH_F`（脚）作自由变量；竖直线约束 `VL`。原片帧叠 100 px 网格读像素坐标，写进 `obs_vN.json`。

### 5.2 相机模型（全程统一）
```python
def Rmat(yaw, pitch, roll=0):          # yaw: 0=+Y(北) 顺时针为正；世界→相机，OpenCV x右 y下 z前
    y,p,r = map(math.radians,(yaw,pitch,roll))
    f = np.array([math.sin(y)*math.cos(p), math.cos(y)*math.cos(p), math.sin(p)])
    r0 = np.array([math.cos(y), -math.sin(y), 0.]); u0 = np.cross(r0, f)
    rr = r0*math.cos(r)+u0*math.sin(r); uu = -r0*math.sin(r)+u0*math.cos(r)
    return np.vstack([rr, -uu, f])
def proj(X, C, R, f, k1=0):            # 1920×804：CX=960 CY=402
    q = R@(X-C); x,y = q[0]/q[2], q[1]/q[2]; d = 1+k1*(x*x+y*y)
    return np.array([960+f*x*d, 402+f*y*d]), q[2]
```

### 5.3 求解顺序（实景、多机位分次拍）
1. **SfM 打底**：每镜头一张中间帧（1280 宽、遮字幕），pycolmap 4.x：`extract_features(PER_IMAGE, SIMPLE_RADIAL)` → `match_exhaustive` → `incremental_mapping`。同机位镜头 C 几乎重合，是归并硬证据。
2. **联合 BA**：房间参数 + 每视图 (C, yaw, pitch, roll, log f, k1) + 人位置，`least_squares(loss='soft_l1', f_scale=2, jac_sparsity=…)`；用有限差分探出的精确稀疏结构；先固定房间再全放开；**多起点**（厅长 × 焦距），挑残差小且物理合理的解。
3. **定房间、逐机位 PnP**；4. **SfM 其余镜头**用 Umeyama 相似变换搬进米制世界；5. 无标定点的手持近景按画面推断，可信度“低”。

### 5.4 有机械约束的多机同拍（环轨/轨道）——《让子弹飞》做法
长焦近景里 SfM 的**位置和焦距是耦合的，只有朝向可靠**。所以：
1. **按“拍谁”分组做 SfM**（每个主角一组，多个子模型对齐合并），只取每帧的朝向 yaw。
2. **零点**：环轨停转时的静止镜头（三机各正对一人）朝向几乎相同（±1.5°），假设它们正对演员，用来给每组定零点。
3. **机位 = 视线与环轨的交点**：从演员头部沿“朝向 + 人脸水平偏移修正”反向作射线，与半径 R 的圆相交 → 环轨方位 θ。
4. **焦距由人脸大小反推**：`f_px = 脸高px × 距离 / 0.21 m`，`hfov = 2·atan(W/2/f_px)`。
5. **俯仰用几何算**，别用 SfM：`pitch = atan((头高−镜头高)/d) − atan((H/2−v)/f_px)`（v 为脸中心纵坐标，注意符号）。
6. **镜头内移动**：每个运动镜头在 f0+2、中点、f1−2 三帧各求一次 (θ, yaw)，存成 `keys=[[f,θ,yaw],…]`；静止/停转镜头取均值、只留一个键。
7. 求不出的镜头按“正对位置”示意，可信度“低”。《让子弹飞》286 个三人镜头解出 262 个。

### 5.5 线框/同机位验收
实景：把房间边线投到原片帧上四宫格看。搭景：用同机位验收相机渲染（`lens = 18/tan(hfov/2)`，36 mm 画幅，1280×536，隐藏所有示意物和机组），和原片并排看构图。

## 6. 第 5 步：逐镜头摄影参数（教学视频的核心信息）

每个镜头都要有下面四项 + 运动描述，写进 plan 和 CSV：
- **景别**：人脸框高 / 画高（YuNet，1280×536 中间帧）。阈值：≥0.80 大特写、≥0.62 特写、≥0.45 近景、≥0.36 中近景、≥0.20 中景、其余全景（YuNet 框偏大，阈值已按它调过）。无脸镜头按机位给默认（插入=特写（插入）、望小隔间=全景…）。
- **焦距**：按 S35 片门换算 `24.89/(2·tan(hfov/2))`，写“≈”；变焦镜头写 `≈起→止 mm` 和倍数。
- **光圈**：用背景烛光的焦外光斑直径反推，`N = f²(Db−Ds)/(c·Ds·Db)`，`c = 光斑直径px × 24.89/画宽px`（mm），背景距人按经验加 2.3 m。只信 1.2–4.5 之间的结果，量化到 T1.4/2/2.8/4；其余用全场中位数，标“按全场估计”。**一律写“T2 左右（推测）”并注明依据**，只作量级参考。
- **机高 / 支架**：环轨 1.2 m · 环形轨道三机同步；固定机位按反求；手持写“手持（推测）”。
- **运动**：环轨 `顺/逆时针移动 X°（Y°/秒，约 Z cm/秒），边移边摇跟人`（移动 ≥0.4° 才算）；`固定（环轨停转）`；`变焦推/拉 k×`；`手持甩镜（肩扛跟拍，快速摇摄）`。
- 人脸检测在云容器跑（用户机器上的 cv2 没有 objdetect）。

## 7. 第 6 步：灯光推断

逐类写证据：窗/帘后背光、画内实用光（烛台、壁灯、百叶后灯泡）、顶部柔光（看人脸布光、桌面高光；环轨 360° 转时地面立不了灯架 → 推断顶挂）。画外解释不了的亮度写“推测”。每盏灯编号 L1…，所有图和视频共用。

## 8. 第 7 步：Blender 场景（模块化脚本，改完重跑）

### 8.1 数据与模块
- 全部数据放 `plan_data_vN.json`：`setups`（id、name、kind=ring/park/fixed/hand/exterior、C、rig、move、conf、color、phases）、`shots`（含 keys、hfov0/1、size、tstop、move、note、可选每镜头 C/yaw 覆盖）、`room`、`props`、`lights`、`lights_geo`、`people`（含分段路径与 pose）、`ring`、`topcam`、`curtain_stages` 等。
- **plan 里如有 `setups_by_id` 这种冗余副本，改 setups 后必须重建它**，否则旧名字（如“舞女”）会残留。
- 模块：build（建场景）、render（prep_shot/anchors/overview/check_render/timer 队列）、anim（子帧更新）、patch（新功能覆盖）。**每个模块都是平铺文件，用 `importlib.util.spec_from_file_location` 加载、存在 `builtins._XXX`**；绝不写“模块里 exec 自己/改 `__file__` 再 exec”的链式加载（导致过三次崩溃）。打补丁替换函数时先存一次原函数（`if not hasattr(R,'_prep_orig')`），防止补丁调用补丁无限递归。
- 所有自己的对象、相机加项目前缀（如 `LBF_`），避免和用户场景重名（曾和用户带驱动器的相机重名）。材料函数会给名字加 `lx_` 前缀，**按名字判断材质时用 `in` 不要用 `startswith`**。

### 8.2 Rodin 素材（人物、关键道具、机组）
- 主角、椅、桌、烛台、酒瓶、剑、首饰匣、摄影机等关键物用 Rodin 生成，提高真实感；群演可以简模。
- 导入后：**旋转模式是四元数**，复制体一律设 `rotation_mode='XYZ'`；正面朝 −Y；顶点归一化到“底部中心为原点、按真实身高缩放”；原件放 `LBF_assets` 集合、隐藏、移到 z=−200，否则会出现在渲染里。
- **生成完立刻存库**：`bpy.data.libraries.write(work/xxx_assets_vN.blend, 对象集合, fake_user=True)`。Blender 崩溃后，用原来的 job 句柄 `generate_3d(job=…)` 还能**免费重新导入**，不要重新生成。
- 道具/工具超长（推车横杆、吊杆）会穿墙：用 bmesh 删掉手以外的顶点再自己补短杆。
- 用过的机组提示词（每个一次生成，复制使用）：
  - 摄影师：`realistic modern film camera operator man standing, black t-shirt, dark cargo pants, baseball cap, both hands held forward at chest height as if gripping camera handles, full body`
  - 跟焦员：`… focus puller woman standing, holding a small wireless follow focus remote …`
  - 推轨员：`… dolly grip man leaning forward pushing with both arms extended …`
  - 吊杆员：`… sound boom operator man standing, both arms raised above head holding a long boom pole, over-ear headphones …`
  - 肩扛手持：`… camera operator holding a professional cinema camera on his right shoulder, handheld shooting pose …`
  - 角色换姿态（站→蹲）单独生成一个姿态模型，按段落切换。

### 8.3 机位与视锥（用户反复纠正过的视觉规则）
- 机身用 Rodin 摄影机模型。**不要加发光球/白色光点当机位标记**——用户会以为真实相机有个大白灯。
- **视锥要淡、要短**：只留细边线（Wireframe 0.011）+ 极淡填充（alpha≈0.06）；当前机位的视锥长度 = 到被摄者距离 − 1.5 m，停在人物前面，**不能盖住人物**；不在拍的机位只留 1.3 m 灰色短锥表示朝向。
- 变焦镜头：视锥按 `hfov0→hfov1` 缩放 (1, k, k)。
- 所有示意几何体 `visible_shadow=False`，否则地面一片黑。

### 8.4 移动机位必须在俯视图里跟着动（用户原话：“这是拍摄的灵魂”）
- 环轨：`RING_ROT` 空物体旋转 θ，三台机 `RCAM0..2` 以 120° 间隔挂在上面；`RCAM0_head` 每子帧按 keys 插值的 yaw 重新瞄准（world yaw 减去父级旋转）。
- 子帧插值：两个键用 smoothstep，三个键分段线性；角度插值先 wrap 到 ±180°。
- 手持镜头：每镜头给自己的 C/yaw（按画面推断），肩扛摄影师挂在机头下，机身对准机头原点。

### 8.5 机组、收音与“让位”
- 每台环轨机配机组（摄影师在机后、跟焦员在侧、推轨员扶推杆），挂在“绕桌心旋转的枢轴空物体”下，跟着环轨一起转。
- **防穿模**：环轨旋转时机组扫过整圈，所以**墙和道具都要放在机组环带之外**。《让子弹飞》：环轨 R=2.9 m，机组 3.0–3.7 m，烛台/盆栽 ≥3.74 m，墙内表面 4.14 m（墙比原示意外移 0.4 m，总图注明位置为示意）。到桌心的半径不随环轨旋转变化，所以直接数值检查：机组所有顶点最大半径 < 道具最小半径 < 墙内表面。
- **收音**：查不到资料就写“推断”。长焦近景头顶有画外空间，推断为吊杆：吊杆员站在某台机旁（不要站在两机之间的空档——那是另两台机拍人时的背景），侧身举杆，杆头伸到桌心上方约 2.4 m（长焦竖直视角很小，画框顶边只比人头略高，入不了画）；无线领夹麦看不见就不画。
- **非环轨镜头（固定、手持、贴地、俯拍）开拍时的现场逻辑**：环轨转到最近的、三台机都不挡该机位视线的角度；挡在视线楔形里或贴着机位/摄影师的机组人员沿半径方向绕到楔形外“让位等候”（面朝桌子等着），吊杆员让位时把杆收回竖起；俯视图标“让位等候”。
- 固定机位配一个站在机后的摄影师；手持机位用肩扛摄影师。非环轨机位只在自己的镜头里显示（`phases=[]`），整段显示会和转动的环轨撞在一起。

### 8.6 剧情状态
- 布帘溅血这类变化：**从原片帧里裁出那块布帘做贴图**，按镜头分阶段换材质（《让子弹飞》：#182 溅上、#185 晕开、#302 加喷溅和流痕），用 UV 平面贴在布帘正面，略带自发光便于俯视可读。
- 人物姿态与朝向逐段写进 `dancer_path` 之类的路径：`{from,to,loc,rot,pose}`；朝向写成“面向某人”。判断站/蹲：看她和坐着的人头部是否同高。

### 8.7 俯视相机
自己拼矩阵，不要用 `to_track_quat`（会滚转）：
```python
pt=rad(pitch); hd=rad(heading)
look=Vector((cos(hd)*cos(pt), sin(hd)*cos(pt), -sin(pt)))
loc=Vector(target)-look*dist
z=-look.normalized(); up=Vector((0,0,1)); y=(up-z*up.dot(z)).normalized(); x=y.cross(z)
M=Matrix((x,y,z)).transposed().to_4x4(); M.translation=loc; cam.matrix_world=M
```
《周处》target (0.4,8.4,0) dist 42 pitch 58；《让子弹飞》heading 90（从南往北看）、pitch 58、target (0,1.0,0.4)、dist 23.5、lens 50、1080×620。墙外移后要拉远，确认四周的墙和小隔间都在画内。

## 9. 第 8 步：渲染驱动（用户 Blender 里的 timer 队列）

- `bpy.app.timers` 队列，每个任务一次渲染，每 tick 2 个，间隔 0.01 s；每 20 个写一次 `_PROG`，完成写 `_DONE`，异常写 `ERR + traceback`。MCP 在渲染期间仍能响应。
- 每镜头：`prep_shot`（环轨角度、机组归位/让位、人物与道具状态、布帘阶段、视锥按本镜头视角重建）→ 子帧更新（只动环轨转角、机头摇角、视锥缩放，便宜）→ 渲染 PNG（透明底）→ `world_to_camera_view` 记锚点：每台机、每个人物、每盏灯、让位人员。
- **子帧**：机位移动 ≥0.3° 或摇 ≥1° 或变焦的镜头，从 f0 起每 3 帧渲一张；静止镜头一张。《让子弹飞》共 2,867 张，EEVEE 64 采样 1080×620 约 0.6 s/张，约 29 分钟。
- 渲染路径每版换目录（`render_anim2/3…`），锚点 key 用 `"镜头号_帧号"`。
- **绝不在 `context.temp_override(scene=…)` 里渲染**（直接导致 Blender 崩溃）。
- 等待长任务：device_bash 单次最长 180 s，用 `timeout 170 bash -c 'until [ -f _DONE ]; do sleep 10; done'` 轮询，期间可以分批合成已完成的镜头。
- 锚点是按当时渲染分辨率算的，换分辨率渲总图时不要再乘倍数。

### 10.2 编码：原始帧管道，帧级精确
PNG 拼接（concat demuxer 时基 1/25）和 overlay 时间戳取整都会造成 ±1 帧误差。做法：Python 逐帧把面板 BGR 字节写进 ffmpeg stdin（移动镜头每帧取“≤当前帧的最近子帧面板”），原片从 film_take 按帧号 trim：
```
ffmpeg -f rawvideo -pix_fmt bgr24 -s 1080x1452 -framerate 24000/1001 -i pipe:0 -i film_take.mp4 \
  -loop 1 -framerate 24000/1001 -i zoom_strip.png -loop 1 -framerate 24000/1001 -i playhead.png -loop 1 -framerate 24000/1001 -i playhead_zoom.png \
  -filter_complex "[0:v]settb=1001/24000,setpts=N[bg];[1:v]trim=start_frame=FS,settb=1001/24000,setpts=N[film];[bg][film]overlay=0:80[a];[2:v]crop=1040:56:x='(t+T0)*30':y=0[z];[a][z]overlay=20:606[b];[b][3:v]overlay=x='19+(t+T0)*1040/TOTAL':y=565[c];[c][4:v]overlay=x=539:y=604" \
  -frames:v NF -an -c:v libx264 -preset veryfast -crf 20 -pix_fmt yuv420p seg_k.mp4
```
- 纵坐标从合成脚本写出的 `layout.json` 读。
- 按 ~40 s 分段（《让子弹飞》15 段）；**device_bash 返回时会杀掉后台进程（nohup/& 都不行）**，所以一次调用里前台并行 7–8 段：`( for k in …; do python3 encode.py . $k $((k+1)) > log_$k & done; wait )`，约 2 分钟一批。
- 拼接：`-f concat -i concat.txt -ss 音频起点 -t 总长 -i 原片 -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -movflags +faststart`。
- **验收**：`ffprobe -count_packets` 帧数 = 镜头帧数和；随机抽 10 个镜头首帧，原片区域和 film_take 第 f−1/f/f+1 帧比差值，最小值必须落在 f；面板区域和对应子帧面板比差值≈JPEG 噪声（约 3）。

## 12. 踩过的坑

**文件与进程**
1. **同一路径写回用户机器，拿到的还是旧内容**（device_commit_files，加 force 也一样）→ 每次换文件名（`plan_data_v7b.json`），写完在设备上 `md5sum`/读字段确认。
2. **device_bash 返回会杀后台进程** → 前台并行 + wait；单次 180 s 上限 → 轮询。
3. 用户机器上不能删文件 → `mv` 到 `_to_delete/`，告诉用户自己删。
4. 用户机器的 cv2 没有 objdetect（人脸检测放云容器）；Blender 里没有 PIL（看图用 `look(image=路径)`）。

**Blender 崩溃与安全**
5. 模块链式 exec 自己 → 崩溃三次。只用平铺模块 + spec_from_file_location。
6. `temp_override(scene=…)` 里渲染 → 崩溃，丢了用户没保存的另一个场景。
7. 同一个 Blender 里出现别的任务的场景时，误在它上面 frame_set、改了 render.filepath → 先检查场景再动手。
8. 和用户对象重名（验收相机）→ 全部加项目前缀。
9. Rodin：新场景没开 hyper3d；四元数旋转让朝向失效；原件出现在渲染里；崩溃后用 job 句柄免费重导入；生成后立即存库。

**同步与数据**
10. 29.97 带重复帧 → 整场一次 decimate；分段 decimate 起点漂移。
11. PNG concat 时基、overlay 取整 → ±1 帧；改原始帧管道 + `setpts=N`。
12. SfM 俯仰不可靠且符号易错 → 几何俯仰。
13. plan 里冗余副本没同步 → 改完重建 `setups_by_id`。
14. 枪口闪光被当成剪辑点 → 闪光测试。
15. BA 不收敛/解到房间外 → 精确稀疏结构 + 多起点 + 合理性筛选。

**画面（用户逐条纠正过的）**
16. 移动镜头在俯视图里不动 → 用户认为丢了“拍摄的灵魂”，必须子帧渲染跟动。
17. 标签深色底框太抢、压住人物 → 透明描边小字、沿径向放外侧。
18. 机位发光球被看成“巨大白灯” → 不加任何发光标记。
19. 视锥太显著挡人物 → 细线淡填充、停在人物前、非当前机位只留短锥。
20. 机组身体和吊杆穿过屏风 → 墙和道具外移、截短杆子、数值检查半径。
21. 拍布帘/小隔间时机组挡在视线里 → 环轨转开、人员让位。
22. 人物朝向、站蹲、称呼不对 → 逐段看原片确认，用片中名字。
23. 参数只写视角不够 → 景别/焦距/光圈/机高四项必须有，并放在俯视图四角。
24. 地面全黑（示意物投影）；俯视相机滚转；锚点重复乘倍数；群演挡主角通道。

**表述**
25. 不转写歌词；推断写“推断/推测”（多机同拍、画外灯、收音方式、光圈、手持机位位置）；用户的判断与原片证据不一致时，拿镜头号和画面依据说明，再按证据做。
