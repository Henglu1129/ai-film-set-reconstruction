# 踩过的坑（现象 → 原因 → 解决）

## 流程层面
- **先做网页原型、手估机位，后来全部推倒** → 手估的机位误差有好几米、十几度，人物和车怎么摆都对不上。
  → 第一天就上 SfM；网页、俯视图只用来做展示。
- **场景先按手估坐标搭好，SfM 只能往里对齐** → 每段机位都要叠多层变换（旧坐标、各子模型、手工关键帧），改一处牵动全身。
  → 先把 SfM 转成米制世界，场景在这个世界里搭。
- **直接上全片** → 问题要到最后才暴露。
  → 先跑 2–3 分钟的试点段，把全链路跑通、过一次审片，再推全片。
- **用户反馈说「第 X 页第 Y 帧对不上」，但没说哪里不对** → 自己对比时要逐项看：机位、楼和门、道具、车、人数、每个人的位置、朝向、动作。
  修改说明要写到具体做法上（「补了车内：车窗摇下、车顶」），不要只写「已修」。

## 机位
- **SfM 在暗处、快速甩镜、进屋出窗时断开** → 正常现象，用手工关键帧补，不要硬调参数。
- **偏航慢慢漂移** → 用街道消失点做「罗盘」（mod 90）逐段校正。
- **比例不对**（人像巨人或小矮人）→ 用站着的人（1.70 m）或已知车身尺寸定比例；不同段可能要不同的比例。
- **验收帧不在采样网格上**（帧号不是 3 的倍数）→ 机位和检测都是插值出来的，看起来「对不上」。
  → 验收帧号一律取 3 的倍数（例如用 4599，不用 4600）。
- **摄影机穿墙**（这次 2016 帧机位在墙里）、**穿进修路围栏**（6768 帧）→ 渲染前沿全程查机位是否落在几何体里面。
  → 把窗洞开大、把围栏缩小，或者微调机位。
- **观察机位（TopCam）进楼或埋进车里** → 把 x 夹在街道范围内；落到车顶上方时抬高到 2.4 m 以上；位置做平滑。

## 人物
- **同一个人在画面里出现好几次** → 自动合并时串了人，或者同一身份同一时刻有两条轨迹。
  → 短轨迹「宁断不串」；主要角色列进 `UNIQUE`，重叠时段只留较长的那条；同类两人 <0.6 m 且重叠 >1 秒的删掉短的。
- **人数对不上**（尤其是远景和路口）→ 远处的小人检测不到。
  → 瓦片检测；仍然漏的，按原片画面用 `put` 手工补人。
- **朝向不对**（该望向窗外的人背对窗、该对话的人各看各的）→ 按优先级取：姿态朝向 → 运动方向 → 面向机位。
  → 对话和推搡用 `PAIRS`；特殊动作直接写 yaw。
- **人在墙里、车里、半空中** → 沿视线把点滑到边界；室内用房间地板高度；脚被切掉时用头顶高度反推距离。
- **伸直的手臂上衣服变形**（这次在 07:26.8）→ 自动蒙皮权重的局限。可以接受就在交付时说明；要修就改权重或换模型。
- **跳跃、攀爬这类大动作对不上**（这次 07:11–07:15 跳上箱子那一下）→ 程序化动作覆盖不到。
  → 手工写关键帧，或者在交付时说明。
- **窗口里要探出半个身子的人、坐在车里的人** → 自动检测摆不出来，一律手工 `put`，并给出动作（坐、探身、持枪）。

## 场景和 Blender
- **审片时把整辆车隐藏了**（因为机位在车里），结果「两个坐着的男人连车一起没了」。
  → 做车内模型（车顶内衬、门内板、带头枕的座椅），默认不给相机看；机位在车里时隐藏车壳、显示车内。
- **门被做成了一个立方体**、**少一扇门**、**少了身后的楼梯** → 门要做门框、门扇、铁闸和门洞里的暗部；勘景清单要列到「人身后的东西」。
- **丁字路口整个没建** → 长镜头最后几十秒常常跑到新的空间，勘景清单要覆盖到最后一帧。
- **道具颜色错乱**（面板变成鲑鱼粉）→ 重建脚本按序号复用了上次留下的旧材质。
  → 材质按颜色命名（`propc_RRR_GGG_BBB`），或者每次重建先清理。
- **枪悬在半空** → 道具的可见性要和持有人绑在一起；开枪前（这次 t < 330 s）不显示。
- **在用户的 Blender 里跑长任务会卡住界面，或者 MCP 调用超时** → 用 `bpy.app.timers` 分批做；绝不重启 Blender。
- **QA 渲染改了场景设置（相机、分辨率、隐藏状态）没恢复** → 一律用 try/finally 恢复；临时物体放进单独的集合，用完连数据块一起删掉。

## 合成
- **成片第一帧是黑的** → 原片输入要加 `setpts=PTS-STARTPTS`。
- **音轨不对**（国粤双语的片源）→ 用 ffprobe 看音轨，显式写 `-map 2:a:N`。
- **字幕卡 concat 列表最后一张不生效** → concat demuxer 要求最后一个文件再写一次（不带 duration）。
- **用户不想要的信息**：人名牌、俯视走位图、右上角时间码、副标题、过长的说明 → 这次全都删掉了，默认就不要加。

## 设备和文件传输
- `device_bash` 单次最长 180 秒 → 长任务用 `nohup … &` 放后台，加日志、加完成标记；一次调用只合成两三段。
- `device_bash` 删不了文件（Operation not permitted）→ 换新文件名，不要覆盖；中间产物列出来请用户自己删，或者申请删除权限。
- **重复写回同一路径，拿到的是旧内容** → 每次写回都用新文件名（v2、v3……）。
- **stage 大文件超时**（约 180 MB 时 wall-clock timeout）→ 在 Mac 上 `split -b 45m`，分批 stage，在容器里 `cat` 拼回，对 md5。
- **「Workspace still downloading」**（Mac 端虚拟机还没就绪）→ 先用 list、stage、commit 这几个工具，过一会儿再用 shell。
- **Mac 断开、Blender MCP「Not connected」** → 提醒用户唤醒电脑、打开 Claude 桌面端和 Blender，先做容器里能做的事。
- **用户挪了项目文件夹** → 开工先 `get_device_info` + `device_list_dir` 确认路径；Blender 里用 `bpy.data.filepath` 确认打开的是哪个文件。
