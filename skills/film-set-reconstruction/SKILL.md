# 根据原片还原 3D 拍摄现场

这套方法来自《大事件》（2004）开场长镜头项目：原片 01:20.8–08:07.7，共 407 秒、9768 帧，一镜到底。
最终交付的是一段 1080×1488 的视频：
- 上层：还原的拍摄现场，从摄影机身后看，带吊臂、轨道车和取景框；
- 中层：原片；
- 底部：每个段落一句剧情、一句镜头运动。

全流程在用户的 Mac 上完成，用的工具是 Blender（通过 Blender MCP 操作）、Mac 端的 shell（device_bash）和云端容器。

先读本文件，动手到某一步时再去读 `references/` 里对应的细节。
`scripts/` 里是可以直接改着用的代码；`scripts/reference/` 是那部片子的原样代码，参数都要换。
每个脚本是干什么的，见 `scripts/README.md`。

## 0. 开工前先和用户确认（这一步省掉，后面会返工）

1. **镜头范围**：要精确到帧的起止时间码。还原范围越长，越要先做试点段。
2. **交付形式**：默认用下面「交付默认值」里的版式。用户想要别的版式，先做一张静帧给他确认。
3. **还原精度**：
   - 机位要不要逐帧对上原片？
   - 人物要不要逐个按原片摆位，还是只做主要角色？
   - 精度每提高一级，人工审片的轮数就会明显增加。
4. **机器和约束**：
   - Mac 是否保持唤醒、Blender 是否一直开着。
   - **不要重启或关闭用户的 Blender**，渲染时也不要。
   - 不替用户填 API Key。
5. **先出计划再执行重活**：SfM、全片检测、整片渲染这类一跑几个小时的任务，先把计划和预计耗时发给用户，等他同意再开始。

**一定要先做试点段**：挑 2–3 分钟、最有代表性的一段，把全链路跑通，给用户看过同机位对照再推全片。
《大事件》先做了 03:00–05:30，这一段暴露了「车内消失」「人物重复出现」等问题，修完才扩到全片。

## 1. 总体流程（每步的产出 → 验收标准）

| 步 | 做什么 | 主要产出 | 过关标准 |
|---|---|---|---|
| 1 | 切镜头、去黑边、抽帧 | `take.mp4`、`sfm/f%05d.jpg`（每 3 帧一张）、接触印样 | 起止帧对上剪辑点；帧号 = take 帧号 |
| 2 | 逐帧识别人、车和骨骼姿态 | `det_*.jsonl` | 抽 10 帧画框检查，小人物也能框到 |
| 3 | 反推摄影机 | 每帧机位 `cam(f) → (C, R)`，单位米、z 朝上 | 线框投影到原片上，车和楼的轮廓对得上 |
| 4 | 搭场景 | Blender 场景（脚本生成） | 勘景清单里每一项都有，摄影机不穿模 |
| 5 | 人物身份与摆位 | 人物实体（逐采样的位置、朝向、动作） | 同一身份同一时刻只有一个人；没人在墙里或车里 |
| 6 | 同机位验收 | 审片 PDF（每 3 秒一组「原片｜渲染」） | 用户逐页过，通常要 2–3 轮 |
| 7 | 正式渲染 | 上层视角的逐帧 JPG | `_DONE` 文件出现、帧数一帧不少 |
| 8 | 合成 | 分段 mp4，拼成成片 | 抽查每段交界、首帧不黑、音轨正确 |
| 9 | 交付与展示 | 成片、展示图 | 大文件要分片传，校验 md5 |

各步的具体命令、参数和坑写在 `references/pipeline.md`。

## 2. 方法论要点（这次真正起作用的做法）

### 2.1 机位反求：SfM 打底，消失点定方向，已知尺寸定比例，手工关键帧补洞

- **直接从 SfM 开始，不要手估机位。**
  - 第一版是凭画面手估关键帧做网页预览，精度远远不够，后来才换成 SfM。
  - 这一步试错浪费了大量时间。
- **抽帧**：每 3 帧一张，缩到 1280 宽。
  - 用掩码遮掉人、车、烧录字幕。COLMAP 掩码格式：`图片名.png`，0 表示忽略。
  - 机位绕回同一地点时，要补「远距离配对」（`pairs_long.txt`），否则闭不了环。
- **焦距**：用消失点求（`scripts/vp_focal.py`），两个正交的有限消失点满足 f² = -(va-p)·(vb-p)。
  - 长镜头通常是定焦，求出一个固定 HFOV 写死，不让 BA 去优化焦距。
  - 《大事件》求出 HFOV ≈ 42°。
- **重力方向**：用每帧的竖直消失点（VVP）做重力先验，再用全局式 SfM 重建（pycolmap）。比增量式稳得多。
- **世界坐标**：
  - 先用 VVP 加权平均算出「上」方向，把模型转正（`reference/gravity_align.py`）。
  - 偏航：把最强的水平消失点转到世界里，街道和楼面的方向应该是 0° 或 90°（mod 90），用它来校正偏航漂移（`reference/street_compass.py`、`yaw_series.py`）。
  - 比例：用站着的人求，脚在地面上，头顶在脚的正上方 1.70 m（`scripts/ground_fit.py`）；或者用已知尺寸的静止车辆（4.3×1.7×1.45 m 量级）。
- **SfM 一定会断成几段**，暗处、快速甩镜、进屋出窗的地方最容易断。
  - 每一段单独求一个 5 自由度的相似变换（绕竖直轴转角、平移 xyz、比例），拟合目标是「已知位置的静止车辆」的检测框（`reference/seg_align_5dof.py`、`scripts/carpose.py`）。
  - 段落之间、SfM 完全失效的地方，用手工关键帧做 Catmull-Rom 插值。关键帧位置用门框、窗台、车身角点这些像素特征反解（`scripts/fit_pose_manual.py`）。
  - 偏航和俯仰的局部偏差，用分段插值的偏移量修正。
  - 全部组装进一个 `cam(f)` 函数（示例 `reference/cam_assemble_example.py`）。
- **先定世界坐标系，再搭场景。**
  - 这次的场景是先手搭的（旧坐标），SfM 只能逐段往旧坐标里对齐，变换叠了好几层，很难维护。
  - 下次应该：SfM 出来先转成米制、z 朝上、街道沿 +Y 的世界，再在这个坐标系里搭场景。
- **验收不用等 Blender**：把关键物体（车、油桶、楼面）的线框直接投到原片帧上（`scripts/wire_check.py`）。对不上就改机位，几秒钟一轮。

### 2.2 人物：先在图像里分轨迹，再定身份，最后投到地面

- **检测**：YOLOX-m 整帧跑一次，再分 3 块方形瓦片跑，这样小人物也框得到；高度 ≥90 px 的人再跑 MediaPipe Pose（`scripts/detect_people.py`）。
  - 每 3 帧检测一次。
  - 在 Mac 上分 4 个进程后台跑，各写一个 jsonl。
- **短轨迹**：纯图像空间里按 IoU 关联。原则是**宁可断开，也不要把两个人串成一个**（`scripts/tracklets.py`）。
- **身份**：把每条短轨迹抽几张截图拼成「身份表」（`reference/id_sheets.py`），由 Claude 看图人工标注身份码（劫匪 / 便衣 / 巡警 / 路人 / 丢弃），写进 `labels.py`。不要指望自动重识别——同一个人换个角度、被遮挡，自动方法就会串错。
- **投到地面**：从机位沿脚点像素打一条射线，求它和地面的交点（`reference/people_to_world.py`）。几条规则：
  - 脚被画面切掉时，不能用框的下沿，改用头顶高度反推距离。
  - 室内段用房间的地板高度（这次是 z=7.2）。
  - 算出来落在楼里或车里的点，沿视线滑到墙面或车身边界上（画面位置不变）。
  - 稳健平滑（中值 + 加权，脚点权重最高），速度上限 3 m/s，观测空档 ≤4 秒的按直线补。
- **朝向**：优先用 MediaPipe 的 3D 骨骼（髋、肩的左右向量）算；没有就用运动方向；再没有就面向机位。对话或推搡的两个人，用 `PAIRS` 指定面对面。
- **去重**：主要角色列进 `UNIQUE`，同一时刻只保留一条轨迹。否则会出现「同一个人在画面里出现好几次」。
- **人工补位**：用户指出不对的段落，用 `drop / path / put` 三个指令手动摆（`reference/entities_staging.py`）：
  - drop：删掉自动结果；
  - path：给定路线；
  - put：在某处摆一个指定身份的人。
- **角色模型**：
  - 先生成正面和侧面的参考图，再用 Blender MCP 的 `generate_3d`（Hyper3D Rodin）生成网格。
  - `scripts/dsj_rig.py` 自动绑定统一比例的骨架，MediaPipe 的 3D 关键点驱动姿态，没有姿态时用程序化的走、站、蹲、坐、举枪动作。
  - 动作切换的地方做 ±0.4 秒的过渡。

### 2.3 场景：先勘景、列清单，再用脚本搭

- 先用接触印样（每 2 秒一张）把摄影机经过的东西**按顺序列成清单**：每栋楼、门洞、窗口、楼梯、招牌、店铺、修路区、车辆、路口形状。
  - 这次三轮返工里，大半是漏了东西：门、楼梯、身后的门、窗口里要探出的人、整个丁字路口。
- 全部用一个 Python 脚本在 Blender 里生成（示例 `reference/blender_build_example.py`），改完重跑就行：
  - 楼体用 bmesh 方块加程序化立面材质，开门洞、凹进去的地方用布尔挖洞；
  - 加 Poly Haven 贴图和阴天 HDRI；
  - 车辆用 Rodin 生成的网格，或者方块拼；
  - 关键帧用批量写入的方式写。
- **摄影机会钻进去的地方要建内部**：
  - 车内：座椅、头枕、门内板、车顶内衬；
  - 房间：四壁、门、窗台；
  - 楼梯间：墙和台阶。
  - 渲染时机位在车里，就隐藏车壳、显示车内。

### 2.4 审片：同机位对照 PDF + 一轮轮改

- 在 Blender 里建一台 `CHK_FilmCam`，逐帧用 `cam(f)` 的机位，画幅、焦距和原片一致。每 3 秒渲染一帧，和原片并排排成 PDF（`scripts/blender_qa_render.py`、`scripts/compare_pdf.py`）。
- 用户按「第 X 页第 Y 帧」反馈。每一条都要落实到具体手段（改机位关键帧、补道具、改走位、改朝向）。
- 下一版 PDF 在对应帧旁边标注「本轮已改：……」，方便用户复核。
- 用户说「其他 OK」才开始整片渲染。

## 3. 工具与运行环境（Mac + 云端容器）

| 用途 | 在哪里做 | 说明 |
|---|---|---|
| 抽帧、检测、ffmpeg 合成 | Mac 的 `device_bash`（Linux 虚拟机，挂载用户文件夹） | 单次调用最长 180 秒；长任务用 `nohup … &` 放后台，写日志，分批查进度 |
| SfM（pycolmap） | Mac 原生：通过 Blender 自带的 Python 起子进程 | `pip install --target pylib_colmap pycolmap`，再用 `PYTHONPATH=pylib_colmap` 启动 Blender 的 python；后台运行、看日志 |
| 搭场景、渲染、验收图 | 用户开着的 Blender（`execute_blender_code`） | 重活用 `bpy.app.timers` 分批做（见下），不要阻塞界面 |
| 数据处理、看图、做 PDF 和展示图 | 云端容器 | 素材用 `device_stage_files` 拉过来；结果用 `device_commit_files` 写回 Mac |
| 长时间等待 | `send_later` 约定时回来查看 | 渲染 3 小时这种，约 1–2 小时后回来查一次 |

Blender 后台渲染：`scripts/blender_bg_render.py`。
- 每个 timer tick 渲染 12 帧，已经存在的帧跳过（可以断点续渲），全部完成后写 `_DONE`。
- 这次 EEVEE 1080×780 的速度约 57 帧/分钟，9768 帧约 3 小时。

更多环境细节和传文件的坑：`references/environment.md`。

## 4. 交付默认值（用户在这次项目里确认过的偏好）

- **版式**：1080×1488，按需要可以不是 9:16。
  - 顶部标题栏 96 px，只放一行标题，没有副标题、没有时间码。
  - 上层拍摄现场 1080×780，左上角角标只写「拍摄现场」。
  - 中层原片 1080×468，从 1920×832 去黑边后缩放，角标写「原片」。
  - 底部字幕条 140 px：第一行是段落时间和小标题，然后一句「剧情」、一句「镜头」。
  - **不要俯视走位图、不要人名牌**，字不要多，重点是上层和中层两段画面。
- 合成脚本：`scripts/compose_part.sh`；字幕卡生成：`scripts/make_captions.py`。
  - 每 1200 帧合成一段，再用 concat 拼接。
  - 原片输入要加 `setpts=PTS-STARTPTS`。
  - 音轨选对（这次是 `-map 2:a:1`）。
- **审片材料**用 PDF，每页 8 组「原片｜同机位渲染」。
- 用中文回复。交付时说明文件在 Mac 上的位置，以及还没对上的地方。
- **展示图**（发朋友圈或微信）：10 张 1080×1440 竖版卡片：
  - 封面
  - 原片素材
  - 识别
  - 机位轨迹
  - 搭场景
  - 摆人
  - 同机位对照
  - 迭代前后
  - 身后视角
  - 成片
  - 模板见 `scripts/showcase_cards.py`；机位轨迹图是在 Blender 里把 `RIG_head` 的逐帧位置连成发光曲线、按段落着色，再把挡视线的一侧楼隐藏掉渲染的。用完把临时物体删干净，不要保存 .blend。

## 5. 最容易踩的坑（完整清单见 `references/pitfalls.md`）

1. **审片时把整辆车隐藏了**（因为机位在车里）→ 用户看到「车里坐着的人连车一起没了」。
   - 解决：做车内模型；机位在车里时隐藏车壳、显示车内。
2. **同一个人出现好几次** → 主要角色按 `UNIQUE` 去重；轨迹「宁断不串」。
3. **人物朝向不对**（该望向窗外的却背对着） → 先看姿态朝向，不行就手动指定朝向或面对面。
4. **门、楼梯、路口漏建，或者门被做成了立方体** → 开工前先列勘景清单；门要做门框、门扇、铁闸、门洞里的暗部。
5. **摄影机穿墙、穿进围栏** → 渲染前沿全程查一遍机位是否落在几何体里面，碰到就加宽窗洞、缩小围栏或挪机位。
6. **枪悬在半空** → 道具的可见性要跟着人物的可见性走。
7. **重建脚本复用了旧材质，颜色错乱** → 材质按颜色命名（例如 `propc_RRR_GGG_BBB`），不要按序号命名。
8. **验收帧不在采样网格上**（帧号不是 3 的倍数）→ 机位是插值出来的，检测对不上。验收帧号一律取 3 的倍数。
9. **同一路径重复写回 Mac，拿到的是旧内容** → 每次换一个新文件名。
10. **超过约 150 MB 的文件传不过来（超时）** → 在 Mac 上 `split -b 45m` 分片，容器里 `cat` 拼回，再对 md5。
11. **ffmpeg 成片第一帧是黑的** → 原片输入加 `setpts=PTS-STARTPTS`；用 `-ss` 前置快速定位。
12. **Mac 的 shell 删不了文件**、`device_bash` 偶尔提示「Workspace still downloading」→ 先改用 list/stage/commit，等一会儿再试；中间产物请用户自己删。
13. **用户可能会挪动项目文件夹** → 每次开工先用 `get_device_info` 和 `device_list_dir` 确认路径，Blender 里用 `bpy.data.filepath` 确认打开的是哪个文件。

- [ ] 推到全片，重复上面的审片
