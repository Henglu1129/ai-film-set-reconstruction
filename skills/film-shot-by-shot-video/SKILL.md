# 视频拉片 SKILL（film-shot-by-shot-video）

> 适用场景：用户指定一部片子和一段时间码（通常 10–20 分钟），要一条可以直接发小红书的**拉片视频**，外加一份**拉片笔记**。
> 镜头检测这一步和图文版 [`film-shot-by-shot-breakdown`](../film-shot-by-shot-breakdown/SKILL.md) 同源，那份 SKILL 的「踩坑清单」同样适用，建议先读。

一句话：**用户电脑分段转码 → 云端截帧 + 三路镜头检测 + 目视核验 → 硬字幕分段 OCR 并人工校对 → 声音事件分类 → 逐镜写 8 个字段 → 逐帧人像分割 + 光源/主色锚点 → Python 逐帧合成，交给 ffmpeg 编码 → 导出 Markdown 笔记**。

首个案例：李沧东《可能的爱》（2026）1:39:24–1:55:52，16分28秒，56 个镜头。成片 1080×1096，约 220MB。

---

## 一、产出物（用户定稿的版式）

**1. 拉片视频**：1080 宽，高度按文字最多的镜头自动算（本例 1096）。从上到下：

| 区域 | 内容 |
|---|---|
| 顶部 0–104px | 左：一行标题「AI 逐镜拉片」（琥珀色）+「导演《片名 英文名》」；下面一行灰字「N个镜头 · M分S秒 · 原片起–止」。右上角固定：「镜号 XX」（琥珀色）+ 时间码「起 → 止」 |
| 原片 1080×608 | 原片画面（含原片烧录的字幕），叠加：**人物轮廓**（细白线，逐帧跟随）+ 四个标注：**景别**（贴在主要人物旁）、**镜头运动**、**布光**（光源上画小圆圈，细线连到文字）、**色调**（主色区域画圆圈连线，标题旁三个自动取色的色块）。标注都是透明底、细白字加柔和阴影，避开人脸、硬字幕和亮区 |
| 时间轴 | 56 个镜头按真实时长排成一条，当前镜头琥珀色，白色播放头；下面一排场景名，当前场高亮 |
| 面板 | 四行：**剧情 / 表演 / 声音 / 分析注释**。栏目名放在等宽的圆角深琥珀底块里（琥珀字），内容统一一种细字体、一个字号 |

字体：开源的**霞鹜文楷 Light**（LXGW WenKai），全部文字只用这一款，层次靠字号和颜色（琥珀 #ECBA62 / 白 / 灰）。

**2. 拉片笔记**（`08_export_notes.py`）：Markdown，包含片段信息、平均/中位/最长镜长、场景结构表、镜头总表（镜号/时间码/时长/景别/运动）、逐镜 8 字段笔记；`--with-dialogue` 时附带每镜台词（只给用户本人，公开发布时去掉）。

## 二、迭代中用户提出、已经固化的要求（别再犯）

1. 镜号、时间码固定在**右上角**，不放进画面。
2. 景别、镜头运动、布光、色调**标在画面上**：布光标在光源附近，色调标在主色上，景别圈住人物轮廓；没有合适位置就放空白处，**不能挡脸**。
3. 面板里**不放台词**（原片画面里已有字幕）。
4. **剧情**只写人物在做什么、在谈什么，**不引用台词**。
5. **声音**：有对白只写「对白」，后面加能确认的环境声/音乐，不复述台词；**车里的镜头别漏了车噪**。
6. **分析注释**不用破折号（——），用逗号、句号。
7. 字体要**细、轻、秀气**，所有内容同一种字体字号，不要有的加粗有的放大。栏目名可以大一点，并加底色块。
8. 行距要一致：每行高度只由该行文字决定，不预留空行；视频高度跟着内容收，别留大片空白。
9. 去掉每个镜头单独的进度条，只保留全段时间轴。
10. 「镜头运动」必须复看 1fps 连续帧确认。本例第 19 镜一开始写成「固定长镜头」，实际是先跟摇进书房再定住；第 20 镜实际是横摇。

## 三、运行环境要点（这次实际踩过）

- **片源在用户电脑上**（4K HEVC MKV，4GB+），`device_stage_files` 单文件上限 400MB，只能在用户电脑上先转码。
- **device_bash 每次调用最多 180 秒，调用结束后台进程会被杀**（`nohup … &`、`setsid … & disown` 都不行）。所以转码必须**分块**，一次调用转一块：4 核下 4K HEVC → 720p 约 1.7 倍速，一块 240 秒正好在时限内。
- 块长取 **240.24 秒 = 5760 帧（23.976fps）**，块与块拼接没有帧漂移；视频块不带音频，音频单独导出一次再合流（`01_device_encode.sh`）。
- device_bash 写在 `$HOME/work` 之类 mnt 以外的文件**不能 stage**；成片要先写进连接的文件夹（例如 `电影资源/<片名>_拉片视频/`），再 `device_stage_files`。首次 stage 可能报 `upload failed`，原样重试一次就好。
- **云端容器网络白名单**：HuggingFace 被拦（403），PyPI 和 GitHub release 可以下。所以：
  - 语音识别：sherpa-onnx 的 whisper（`github.com/k2-fsa/sherpa-onnx/releases/download/asr-models/sherpa-onnx-whisper-turbo.tar.bz2`）+ `silero_vad.onnx`
  - 声音事件：`…/audio-tagging-models/sherpa-onnx-ced-base-audio-tagging-2024-04-19.tar.bz2`
  - 人像分割：`pip install ultralytics` + `github.com/ultralytics/assets/releases/download/v8.2.0/yolov8n-seg.pt`
  - OCR：`pip install rapidocr_onnxruntime`（模型在 wheel 里）
  - 字体：`github.com/lxgw/LxgwWenKai/releases/latest/download/LXGWWenKai-Light.ttf`（`api.github.com` 可能被拦，直接用 `releases/latest/download/` 链接）
- 交付：`SendUserFile` 拿到 `file_uuid`，再 `device_commit_files(fileUuid=…)` 写回用户文件夹。直接用 `stagedPath` commit 大文件会报 HTTP 400。

## 四、流程（含命令）

工作目录记作 `$W`（云端），脚本目录记作 `$S`。每一步的脚本都在 `scripts/`，开头有用法说明。

### 第 0 步：确认片源
`device_list_dir` 找到文件；`ffprobe` 看分辨率、帧率、音轨、有没有字幕轨。**没有字幕轨不等于没有字幕**：截一帧看画面里有没有烧录字幕（本例是 4K 片源带烧录中文字幕）。

### 第 1 步：用户电脑分块转码（每次 device_bash 一块）
```bash
# 片段 1:39:24–1:55:52 → START=5964 TOTAL=988，共 ceil(988/240.24)=5 块
bash 01_device_encode.sh chunk "$SRC" 5964 988 0 $HOME/work     # 0..4 各一次调用，timeout_ms=180000
bash 01_device_encode.sh audio "$SRC" 5964 988 $HOME/work
bash 01_device_encode.sh concat $HOME/work "$HOME/mnt/<连接文件夹>/<片名>_拉片视频/clip.mp4"
```
然后 `device_stage_files` 拿到云端，复制到 `$W/clip.mp4`。

### 第 2 步：云端截帧 + 音频
```bash
ffmpeg -i clip.mp4 -vf "fps=1,scale=640:-1" -q:v 4 frames/f_%05d.jpg
ffmpeg -i clip.mp4 -vn -ac 1 -ar 16000 audio16k.wav
```
先拼一张总览图（每 8 秒一帧，8 列），看一眼全段，同时确认硬字幕位置。

### 第 3 步：镜头检测与核验（`02_detect_cuts.py`）
- 三路检测：`AdaptiveDetector(2.5)` 基线、`AdaptiveDetector(1.8, min_content_val=10)` 低阈值、`HashDetector`。**以基线为准**，只核验三者的分歧点。
- 低阈值那一路在静止长镜里会吐出**间隔恰好约 10.4 秒的周期性伪切点**，看到这种等距切点直接忽略（图文版坑 #18 的同类问题）。
- Hash 会把**车从镜头前掠过、镜头跟着横摇**误判成切点（本例 76.8 秒）；前景有摩托车、出租车穿过画面时也会多出切点。对每个分歧点，用 4fps 小图拼 montage 目视确认（`ffmpeg -ss T -t 18 -vf fps=4,scale=240:-1` → `montage -tile 12x`）。
- 对每个保留下来的切点算一次两侧 1fps 帧的灰度均差，均差小于 8 的要复查。本例 55 个切点全部大于 8。
- `02b_build_shots.py` 生成 `shots.json`（含采样帧、重叠字幕、声音标签），并出 8 镜一页的帧拼图 `verify/sheet_*.jpg`。

### 第 4 步：硬字幕 → 台词时间轴（`03_subtitle_segments.py` + `03b_subtitle_sheets.sh`）
- 不要每帧 OCR：先用「白字 + 附近有黑描边」做字幕带 mask，6fps 取样，按 mask 的 IoU（>0.55）判断是不是同一条字幕，得到每条的起止；短于 0.45 秒的丢掉。
- 每条字幕取中间帧放大 2 倍再 OCR。**OCR 错字很多**（「纪录片」识别成「理录片」、「美玉」识别成「美呈」等），必须把字幕带拼成校对页，逐页用 Read 看图，把正确文字写进 `fixsubs.py` 的 `T` 字典。
- **两行字幕的第一行常被裁掉**：对这些编号重新从视频取一条更高的字幕带（`crop=900:110:190:565`）再看。用 ffmpeg 在 `while read` 循环里取帧时要加 `-nostdin`，不然 ffmpeg 会吃掉循环的输入。
- 说话人：按画面和上下文人工标在 `analysis.py` 的 `SPK`（字幕编号 → 人物），只有导出带台词的笔记时才用。
- 没有烧录字幕：用 `04b_asr_whisper.py` 转录原语言，再由 Claude 翻译校对。

### 第 5 步：声音（`04_audio_tags.py`）
每 2 秒一次 AudioSet 分类，按镜头聚合前 5 个标签。AI 听不到声音，「声音」一栏**只写能确认的**：Music 概率高的段落写配乐，并按 Piano、Marimba 等乐器标签描述音色；Cricket、Ocean、Vehicle、Sewing machine 写成环境声。有台词的镜头写「对白 + …」。

### 第 6 步：逐镜分析（写 `analysis.py`）
- 56 镜以内可以自己写：看 `verify/sheet_*.jpg`（每镜 5 帧），对照 `shots_digest.txt`（字幕 + 声音标签），一次写完 8 个字段。上百镜再按图文版的方法分批派 agent。
- 字段与长度：景别 / 镜头运动 / 布光 / 色调 各一行（≤20 字，要上画面）；剧情 1 行；表演 ≤2 行；声音 1 行；分析注释 1–3 行。
- 遵守第二节的写作规范；`SCENES` 把镜号无缝分成若干场。
- 写完后搜一遍「——」：`python3 -c "from analysis import A; print([n for n,v in A.items() if '—' in v[7]])"`。

### 第 7 步：画面标注的素材
1. **逐帧人像分割**：`05_person_seg.py`（后台跑，约 20 帧/秒）→ `seg.pkl`，每帧每人一个归一化多边形 + 框。
2. **光源 / 主色锚点**：`06_anchor_grid.py` 出 10×6 网格三联帧，逐页读坐标写进 `anchors.py`。规则：
   - 只给**固定机位、能看到光源**的镜头写布光锚点（车窗、窗户、挂灯、月亮）。运动镜头、看不到光源的镜头不写，标签会自动放到空白处、不画线。
   - 先运动后定住的长镜头，用第三个值写「从第几成开始有效」（本例第 19 镜写 0.32）。
   - 网格读数常有半格左右的误差，所以布光锚点渲染时会**吸附到 75px 内最亮的点**。半径不要放大，否则会吸到白衣服上。
3. **色块**：每镜中间帧做 k-means（7 类），按「像素数 ×（0.2+饱和度）」排序，压低近黑色，取差异明显的 3 个。只按像素数取，夜戏会得到三个黑色。

### 第 8 步：渲染（`07_render_video.py`）
```bash
python3 07_render_video.py $W still 290 612 830 950   # 先抽帧看版式，Read verify/v3_*.png
nohup python3 07_render_video.py $W full out.mp4 > render.log 2>&1 &   # 2 核约 30 帧/秒，16 分钟片段约 13 分钟
```
实现要点：
- ffmpeg 解码出 1080×608 的 rgb24 → Python 逐帧合成 → 管道给 ffmpeg（x264 veryfast crf 20，音频直接 copy 原片）。面板按镜头缓存，画面标注层按（镜头, 阶段）缓存，每帧只做两次 alpha 混合和画轮廓。
- **标签自动避让**：每个镜头建一张 1/8 分辨率的「占用栅格」，由这几项叠加：人物 mask 在本镜所有采样帧上的并集；人物框上部 32% 的脸部区域加权 ×2；亮区（亮度超过 0.55 的部分）；硬字幕带（画面底部 80%–97% 高度、15%–85% 宽度，权重 3）。在栅格上逐位置算平均占用，取代价最小处，同时不和已放的标签、任何锚点重叠。有锚点的标签加距离惩罚，尽量靠近锚点。景别标签的锚点取主要人物框侧边 38% 高度处，左右各试一次。
- **人物轮廓**：按景别里的人数取面积最大的 k 个人（单人 1、双人 2、三人 3、四人 4、群像最多 5、空镜 0；面积小于画面 0.6% 的不画）；mask 在半分辨率上做高斯模糊和 EMA 平滑（0.55/0.45）后取轮廓；**把贴着画面边缘 6px 的线段去掉**，否则大面积前景人物会在画面四周画出一个白框。
- 面板高度：先算所有镜头里文字最多的那个，再定整条视频的高度。

### 第 9 步：拉片笔记
```bash
python3 08_export_notes.py $W --with-dialogue -o <片名>_视频拉片笔记.md   # 给用户本人
python3 08_export_notes.py $W -o 公开版.md                               # 不含台词
```

### 第 10 步：检查与交付
- 在几个切点前后各 0.1 秒抽帧，确认画面切换时镜号和面板同步换；再抽几帧有长文字的镜头，确认不溢出。
- 写进连接的文件夹，在回复里说清楚**哪些是推断、可能不准**：说话人、声音栏的配乐判断、轮廓抖动或圈错（虚焦前景人物、遮挡、刚入画的几帧）。

## 五、踩坑清单

1. **device_bash 后台进程活不过一次调用**：nohup、setsid 都会被杀，长任务只能拆块，每块控制在 180 秒内。
2. **OpenCV 用 `CAP_PROP_POS_MSEC` / `POS_FRAMES` 跳帧不准**：H.264 下可能拿到前后几秒、甚至别的镜头的画面。做网格图、选锚点一律用 ffmpeg 抽出的 1fps 帧；渲染时顺序解码，不跳帧。
3. **网格读数有误差**（本例月亮的 y 坐标差了约 0.05）：布光锚点要吸附最亮点，色调锚点圈的是一片区域，影响不大。
4. **调色板只按像素数排，夜戏全是黑色**：要按饱和度加权。
5. **大面积前景人物的轮廓会沿画面边缘画出白框**：去掉贴边线段。
6. **白字压在亮背景上看不清**：亮区计入占用代价；阴影用「MaxFilter(3) + GaussianBlur(3)」，透明度放到 1.25 倍。
7. **标签离别人的锚点太近，容易让人以为指的是那个圆圈**：放标签时避开本镜所有锚点。
8. **为台词预留两行，会让单行台词下面空出一大块**：行高只由实际文字决定（最后整行台词也删了）。
9. **低阈值检测器在静止长镜里会出等距伪切点，Hash 会把横摇跟车当成切点**：都以基线为准，分歧点逐个目视核验。
10. **OCR 不可信**：校对必须对着图逐条做；两行字幕要重新取更高的字幕带。
11. **`while read` 循环里的 ffmpeg 会吃掉 stdin**：加 `-nostdin`。
12. **HuggingFace 被拦**：模型改从 GitHub release、PyPI 拿（见第三节）。
13. **ffmpeg 的 drawbox 不支持按帧变化的宽度**（`w='t*…'` 只在初始化时算一次）：动态进度条、播放头之类改在 Python 里画。
14. **大文件不能用 `stagedPath` 直接 commit**：先 `SendUserFile`，再用 `fileUuid` commit。
