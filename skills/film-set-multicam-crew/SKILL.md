# 多机位剪辑戏的拍摄现场还原（轮次 + 参数 + 剧组）

在 film-set-multicam（机位还原）的基础上，多做三层：
- **拍摄轮次**：成片里的多机位通常不是同时拍的（会互相穿帮），而是分几轮拍，每轮一个朝向、一套灯光。
- **逐镜头摄影机参数**。
- **拍摄现场**：演员连续走位、摄影机、摄影师、吊杆员、灯光。

产物：竖版 1080×1920 教学视频，从上到下依次是：
- 原片 + 中英双语字幕
- 细时间轴
- 摄影机参数卡
- 当前轮的 3D 俯视现场
- 14 轮（按实际轮数）拍摄缩略图

另外交付：机位总图、轮次方案、逐镜头参数表、.blend，以及一组 9 张「制作过程」说明图。

来源项目：《婚姻故事》公寓争吵戏 1:31:15.9–1:41:26.8，147 镜 → 30 机位 → 14 轮。

## 0. 先对齐的口径（开工前和用户说清）
- **一轮**：同一朝向、同一套灯光与走位里依次拍的一组机位；推不出拍了几条。
- **单机还是多机**：先查制作资料。摄影师访谈里说「我自己掌机，现场就我、场务、录音」= 单机。单机时，**同一时刻现场只有一台摄影机**，一轮就是一个朝向块里单机依次换机位。
- **轮次编号**：真实拍摄先后成片里看不出来。默认（用户确认过）按成片里首次出现的顺序排，成片第 1 个镜头属于第 1 轮。要在交付里注明。
- **文案**：一律写「第 X 轮拍摄」「共 14 轮」，不要只写「第 X 轮」，外行看不懂。
- **中途检查点（必须）**：先交「机位与轮次确认稿」（网页 artifact：泳道时间轴、户型示意、每轮机位代表帧 + 证据 + 可信度、待确认问题），用户确认分组后再做 3D。
- **器材**：查幕后采访拿真实机型，例如 ARRICAM ST · Panavision Primo 定焦 · Kodak 35mm 200T 5213 · 1.66:1。写进标题栏，并注明「全片设备，据采访」。

## 1. 切片与剪辑点
- 代理片做法：`ffmpeg -ss T0-5 -i src -t N -vf scale=320:-2 -an -sn -c:v libx264 -preset ultrafast -crf 22 -g 1 proxy.mp4`。全 I 帧，逐帧分析快。
- 剪辑点算法：
  - 64×40 LAB 缩略图差 + HSV 直方图：`D=0.5*thumb/40+0.5*hist`，取局部极大。
  - D≥0.4 直接认。
  - 0.1–0.4 且 D 是局部中位数的 2.2 倍以上的，出「前一帧 | 后一帧」对照图人工看。
- 常见误切：前景人物或门板扫过时，D 在 3–5 帧内递增，这是连续运动，不是切点。
- 每镜头首/中/尾三帧印样全看一遍。全分辨率帧用 `xargs -P6` 并行 `-ss` 单帧抽取，不要用几百项的 select 表达式，极慢。
- **起止点**：分析阶段，开场门板或前景遮挡造成的暗帧常是镜头的一部分，别切掉。最终成片可以从人物露脸那一帧起（用亮度曲线找门开到稳定的帧），音频同样平移。

## 2. 机位归并（证据可量化）
- **同机位硬证据**：两镜头中间帧先用 YOLOX 框掉人物，再做 SIFT + `estimateAffinePartial2D`。
  - 背景缩放≈1.000、位移小 = 同机同镜头。
  - 缩放≈1.3 = 换镜头或挪机。
  - 只有横移 = 摇。
- 同机位内俯仰偏移成簇，往往对应不同条次。
- **固定机位横摇**：两帧之间是纯旋转，用单应矩阵解焦距（K⁻¹HK 正交化扫 f），比 SfM 自标定稳得多。
- SfM（pycolmap，容器里可以 pip 装）在白墙多的室内常只拼出几个子模型，焦距和纵深耦合，只作佐证。
- 大特写背景虚、没有特征点：按内容归组，标可信度。

## 3. 轮次推断
证据从强到弱：
1. 制作资料（单机还是多机）。
2. 过肩正反打剪辑点两侧的动作是否衔接：抽「前镜尾帧 | 后镜首帧」（间隔约 4 帧），放大看手、头、身体位置；对不上 = 分次拍。
3. 多机时的穿帮冲突：A 在 B 视锥内且没被人挡住，就不可能同时开机。
4. 朝向和灯光：同一面墙为背景、同一套光的机位归一轮；正打和反打分两轮。
5. 惯例：主镜头（全场摇拍或长镜头）单列一轮；同方向景别递进（中景 → 近景 → 大特写）归同一轮。

运动跟拍、近身对吼这类证据弱的单列一轮，标「低」。

## 4. 户型与机位反求
1. 先找一个能看到整面墙的主机位。LSD 线段看竖线是否平行（判断俯仰≈0），墙上水平线交出消失点得到朝向，用门高（门套顶约 2.03–2.10 m）定比例，算出机位到墙的距离、机高、房宽、门窗位置。
2. 主机位横摇帧继续定其他墙、厨房、隔断。反打方向用两个已知点（如两盏台灯）的方位角交会求机位。
3. 写参数化房间：墙折线、门窗洞口、**所有家具的包围盒**（含边几、台灯柜、餐椅、落地灯，后面做避让要用）。
4. 把线框投到原片上验收，几秒一轮，不用开 Blender；对不上就改。
5. 只看到一面墙的长焦机位，焦距和距离沿视线耦合：给 f 先验 + 机高先验求解，接受约 0.5 m 精度。
6. 近景没有地标：按人物位置和背景内容推断，标「低」。
7. 画一张 matplotlib 二维平面图（墙、家具、每个机位的扇形、人物路径），检查有没有机位进墙、朝向反了。
8. **摄影机视角核对**：在 Blender 放同位置、同焦段的虚拟摄影机渲染，和原片关键帧对照（墙临时拉到全高、补光）。本项目核对了 32 组。

## 5. 逐镜头数据 `plan_data.json`
- `setups`：id、name、C、yaw（北=0，顺时针）、pitch、hfov、rig、conf、shots、pass_id、rep（代表镜头）。
- `shots`：n、f0/f1、t0/t1、tc、dur、setup、pass_id，该镜头实际的 yaw/hfov/pan 范围，`C`/`N` = [起点, 终点, 姿态 stand/sit/kneel]。
- `passes`：id（按首次出现）、name、short、dirn、setups、conf、color（正反打成对，用同色系深浅）。
- `traj_dense`、`facing`、`cam_yaw`：见第 6、7 节。

## 6. 演员连续走位（每 0.5 秒一帧）
- **抽帧检测**：2 fps 抽 960×576 帧。人物用 YOLOX-s ONNX（onnxruntime；ultralytics/torch 装太慢）。人脸用 OpenCV YuNet（`FaceDetectorYN`）。
- **地面坐标**：两条线索，按可信度融合。
  - 脚点投到地面：`Rmat(yaw,pitch)` 反投影射线和 z=0 求交。
  - 人脸距离：`r=f·0.23/face_h`。
- **身份**：用匈牙利匹配（方位角 + 衣服颜色评分），加门限去掉离群点。
- **平滑**：最小二乘平滑（λ≈6）加先验位置；姿态分 stand/sit/kneel。
- **朝向**：综合人脸关键点（鼻子相对两眼中点的偏移）、肤色比例（判断正面还是背面）、运动方向。
- 输出 `traj_dense`（0.5 s，线性插值）和 `facing`。用关键帧核对，发现「时差」或偏差的局部改先验再重算。

## 7. 逐帧摇移（让 3D 摄影机和视锥跟着摇）
- 在代理片上逐帧做 LK 光流 + 仿射 RANSAC，得到 `[tx,ty,scale,inliers]`。镜头最后一帧记为空。
- 换算成角度：`f_proxy=160/tan(hfov/2)`，`Δyaw=-atan(tx/f)`，`Δpitch=+atan(ty/f)`，在镜头内累加。
  - 固定机位：σ=4 帧平滑，摇幅 <1.2° 就拉平。
  - 手持：σ=1.2，保留晃动。
- **绝对朝向锚定**，按优先级：
  1. 人工锚：用门框等已知方位，例如某帧门在画面中心偏多少度。
  2. 和跟踪得到的 `cam_yaw` 求中位偏移。
  3. 镜头均值 = 该镜头的反求 yaw。
  - 主镜头可以用「起点 = 主机位 yaw」，再看摇到的方向是否正好对上另一个已知朝向，用来互相印证。
- 缩放项受前景人物影响大，不要用来推轨。移动机位（跟拍）用「跟在被拍者身后 0.9 m」的规则移动机身。
- 输出 `camtrack.json`，每帧 yaw/pitch。

## 8. 摄影机参数卡（逐镜头）
| 参数 | 怎么得到 | 标注 |
|---|---|---|
| 景别 | 人脸高度占画面比例分档（特写 / 近景 / 中近景 / 中景 / 中全景 / 全景） | 实测 |
| 焦段 | S35 等效 `24.89/(2·tan(hfov/2))` | 实测 |
| 焦点和背景虚化 | 人脸区与背景区的清晰度对比（重模糊梯度法） | 实测 |
| 景深 | 按焦段、对焦距离、T2.8、CoC 0.025 算近界、远界和总景深，画示意条（摄影机 → 焦平面 → 背景墙） | 计算 |
| 光圈 | 胶片和光线推断（T2.8） | 推断 |
| 运动 | 摇 / 跟 / 固定，取自运动和支撑分类 | — |
| 支撑、摄影师姿态、录音方案 | 见第 9 节 | 推断 |

- 支撑分类依据：高通抖动 + 滚转，分固定、稳定跟摇、手持、不确定四类。
- 每个格子右上角标「实测 / 推断」。

## 9. Blender 现场（用户的 Blender 里新建独立场景 `MS_Set`，资产放 `MS_Lib/MS_Assets`，不动原场景）
### 房间与视角
- 墙在约 1.15 m 处剖切，加深色墙帽；窗用发光玻璃条，门洞留空。吊柜、冰箱高度不超过剖切面。
- 俯视相机自己拼矩阵（target、距离 16.5、俯角约 60°、北在上），不要用 to_track_quat。
- 俯视渲染地面过曝时：降面光，地面和墙用中灰偏暖。

### 资产
- **Rodin 生成**（`generate_3d`，provider hyper3d，一次一个，等待超时就用 job 句柄续等）：
  - 两位演员的站 / 坐 / 跪姿。
  - 沙发、扶手椅、茶几、餐桌、落地灯、门、百叶窗。
  - 站姿和跪姿摄影师、举杆吊杆员、**拄杆待命的吊杆员**、导演（导演椅 + 耳机）、录音师（调音台前）。
  - 监视器、录音车、移动车、三脚架。
- **归一化**：把旋转烘进网格，统一「正面朝 +Y、底面 z=0、真实尺寸」，再移进 `MS_Assets`。场景里用 `bpy.data.objects.new(name, src.data)` 共享网格实例化。
- **摄影机不要用 AI 生成**：分不清镜头朝哪，各帧大小不一。按实拍照片做程序化模型，全片唯一、1:1 尺寸。以 ARRICAM ST 为例，部件有：方形机身、顶置 1000 尺圆角暗盒、PL 卡口、Primo 镜头 + 白色对焦环、导轨、开口遮光斗、机身左侧取景臂和目镜、跟焦器、提手。原点放在镜头卡口，+Y 朝前。
- **摄影师衣着**：换浅色明亮衣帽，和深色摄影机拉开对比。做法是复制材质，按物体空间 z（腰线以上）且非肤色（HSV 判断）的区域乘一个浅薄荷色。

### 每帧状态（prep_frame）
- **只显示一台摄影机**：当前机位显示摄影机 + 支撑 + 摄影师。本轮其他机位只留淡色地面圆环和很淡的视锥，**绝不放悬空空机身**，否则看起来像镜头飘着、相机叠在一起。缩略图模式可以显示本轮全部机位的机身和支撑，不放人。
- **支撑**：手持 = 站立肩扛；机高 <1.2 m = 跪姿；其余站立。三脚架按机高缩放高度，移动车按柱高缩放，放在机身中心下方。
- **摄影师站位要避让**：机身后 0.38 m（肩扛）/ 0.62 m（跪）/ 0.72 m（三脚架）。如果嵌进家具或墙，依次转 ±25°、50°、75°、100° 找空位。
- **挪家具**：机位占了家具的位置，就像真实拍摄那样挪走。本项目拍 C1 时挪走扶手椅，拍 A1 时挪走边几和台灯。摄影机架在沙发前沿时，摄影师和三脚架抬到坐垫高度（0.42 m）。
- **让位**：单人镜头里机位占了对手演员的座位，对手演员起身站到画外。站位要满足：不在视锥内、不在摄影师身后、不撞家具，面朝被拍者对戏。本项目拍 Nicole 时，Charlie 站到沙发北头外侧。
- **演员碰撞**：演员离摄影机 <0.5 m，或离摄影师、补光、吊杆员 <0.45 m 时，沿径向推开。
- **吊杆员**（预计算 0.5 s 轨迹）：
  - 不在本轮任何视锥内（偏角 > hfov/2+12°）；杆子不穿墙，只能从门洞穿过；避开所有家具、补光、摄影机和演员；走动有速度上限。
  - 话筒放在被拍者头顶前上方约 0.5 m。
  - 录音方案是「领夹为主」（远景天花板入画）时，换拄杆待命的模型，站在摄影机后方画外，不举杆。
- **灯光（推断，单独一层）**：
  - 窗外大灯 + 柔光布作主光，地面画淡黄色窗光。
  - 厨房窗外一盏小灯。
  - 室内补光用**柔光箱 + 灯架**：亮面朝演员，逐镜头放在画外、摄影机侧前方，避开机位和摄影师。不要用黑盒子灯头，会被看成第二台相机。
- **导演·录音监视区**：放在相邻房间，导演和录音师并排坐在监视器和录音车前。
- **其他**：
  - 门开合动画。
  - 近 5 秒走位点阵。
  - 两人之间的黄色虚线轴线（让位时仍按原座位画）。
  - 视锥长度 = 到被拍者距离 + 0.45 m（截在 1.2–4.2 m），否则长焦视锥穿墙；材质用淡色、低透明度，免得挡住人物。
- **锚点**：渲染时写 `anchors.jsonl`（world_to_camera_view，按当时分辨率，换分辨率不要再乘倍数），记录 people、crew（摄影师、吊杆员、监视区）、lights。**不写房间名**：用户要求删掉客厅、厨房等地名。

### 渲染
- `bpy.app.timers` 每个 tick 渲染 4 张，**隔帧渲染**（range(0,N,2)），730×730，约 3 张/秒，7323 张约 40 分钟。
- 每轮缩略图 `pass_XX.jpg` **先同步渲染**（否则合成要等到最后）。
- 进度写 `_PROGRESS`，结束写 `_DONE`。
- 模块改版换文件名，用 spec_from_file_location 加载成 `sys.modules['ms_build']`。
- 新功能用「保存旧函数 + 重定义」的方式叠加。注意全局名在调用时才解析，覆写 `place_fill` / `place_boom` / `set_rig` 会自动生效。
- .blend 只导出 `MS_Set`、`MS_Lib` 两个场景：`bpy.data.libraries.write(path,{scenes},fake_user=True,compress=True)`，换新文件名。不要 save_as_mainfile，会带上用户自己的场景。

### 自动体检（每次改完都跑）
在容器里用同一份家具表、墙多边形、camtrack、boom/fill/standby 数据，逐镜头采样 6 个时刻，检查：
- 机身、摄影师、补光、吊杆员是否嵌入家具或穿墙；
- 演员和机位、摄影师、补光、吊杆员是否重叠；
- 吊杆员和补光是否撞位。

列出问题后再修；再挑 12–14 个代表帧渲染拼图目检。

## 11. 字幕与编码（帧精确）
- **字幕**：从源 mkv 截一段带字幕轨的 clip.mkv，找出中英双语的位图字幕轨（本项目 s:2）。
  - 用 `color=black@0` 透明底 overlay 字幕轨 → trim → crop 字幕带 → 缩放后叠到原片下沿。
  - 不要对字幕轨做输入端 -ss，否则字幕会消失；要从 clip 开头解码再 trim。
  - 长句别放大（ENL=1.0），否则左右被裁。
- **面板到帧**：每个输出帧建一个符号链接，指向 `p_{f-f%2}.jpg`。切镜头和面板切换天然同帧。
- **分段编码**：每段 1000 帧，一次 device_bash 编 2–4 段（单次 180 s 上限，前台跑，后台会被杀）。
  - 输入：`-framerate 24000/1001 -start_number a -i links/f_%05d.jpg`。
  - 原片：`-ss T0+a/fps`，`scale=1080:648, fps, setpts=N/(24000/1001)/TB`，overlay 到 y=64。
  - 播放头：透明 PNG 竖线，`overlay=x='X0-7+(t+a/fps)*(X1-X0)/TOTAL'`。
  - 输出参数：`-map_chapters -1 -dn -an -preset veryfast -crf 19`。
- **合并**：concat demuxer + 源音轨，`-ss T0+START/fps -t (N-START)/fps -map 1:a:0 -ac 2 -c:a aac -movflags +faststart`。
- **验收**：`nb_read_packets` = 帧数；抽段接缝前后帧、若干剪辑点前后帧、多个时段拼一排看同步。

## 14. 踩过的坑
1. 写回电脑时，同名暂存文件可能拿到旧内容：每次换暂存文件名和目标文件名。
2. 电脑上没有删除权限：输出一律覆盖或换名，不要依赖 rm。
3. 设备连接会断：告知用户并排一个稍后重试；恢复后从 `_PROGRESS` 断点续跑（start_frames 会跳过 anchors 里已有的帧）。
4. 源 mkv 的章节会变成数据轨，导致 concat 只剩第一段：每段都要 `-map_chapters -1 -dn`。
5. 一次编码太多段会超时：每次 2–4 段，缺面板的段等渲染跟上再补。
6. 肉眼在网格图上读点做全量 PnP 太慢且不稳：先用消失点 + 已知尺寸解主机位，再交会或线框微调。
7. 白墙多的室内，SfM 只能佐证，不要直接用它的位置。
8. cam_yaw 插值不能跨镜头。
9. 走位的地面点有离群值、身份会串：先门限，再做匈牙利匹配。
10. Rodin 资产朝向任意：先把旋转烘进网格再统一。Rodin 生成的摄影机部件含糊，不要用。
11. 同轮多个机位都放机身，会出现「镜头飘着」「相机叠在一起」：单机拍摄只显示当前那一台。
12. 补光做成黑盒子，会被误认成相机。
13. 避让表漏了小家具（边几、台灯柜、餐椅），演员和剧组会嵌进去：家具包围盒一个都不能少。
14. 摇镜的绝对朝向如果只用跟踪结果（被限制在 ±22°），大摇镜会被压扁：要用光流积分 + 锚点。
15. 证据文字或面板里写了「第 N 轮」，轮次重排后要同步改。
